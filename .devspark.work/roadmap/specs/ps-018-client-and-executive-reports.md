# ps-018: Client and executive reports

## Outcome

Repeatable reports for a portfolio, client, project, application, or repository over a chosen period, with
an executive summary and technical detail, as a browser view, HTML, and downloadable PDF, optionally
generated monthly.

## Current Reality

`unified_report_generator.py` produces markdown reports for a GitHub user; no client-level, period-based,
or multi-source report exists. Data sources available at this point are whatever earlier items delivered.

## Scope and Independence

In scope: deterministic report builder over stored observations covering only the capabilities that have
data (monitoring coverage and freshness, security, dependency maintenance, releases, availability,
functional checks, performance, search/traffic when present), period-over-period changes, outstanding
risks, recommended actions generated by rules; each figure carrying a source observation reference and
timestamp; missing data listed explicitly; HTML-to-PDF rendering using a headless browser already in the
stack (or a lightweight library if simpler); scheduled monthly generation and a manual run; optional email
delivery only if a channel exists; report artifacts stored under the artifacts volume and not published
publicly.

Out of scope: AI text (ps-019), a client login portal, white-label branding.
Standalone: reports degrade gracefully with whatever data exists.

## Future Health

Sections are modules keyed to capability so new collectors add sections without changing the framework.

## Dependencies and Decisions

Depends on ps-005 so client data is protected. Open: PDF approach; email delivery in scope; report templates.

## Completion Expectations

A client report for a period includes only observed data with traceable references; removing a data source
omits its section with a stated reason; PDF opens and matches the HTML; no private data is reachable
through public paths; pytest covers period math, missing-data handling, and references.
